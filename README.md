# TalkEQ 沟通情商教练

**简体中文** | [English](README.en.md)

通过真实感情境、作答反馈和薄弱项复练，练习清晰、自然、有边界的沟通。每次默认约 **5–10 分钟**，也可以直接带一条消息来修改或复盘。

TalkEQ 是一个供支持 Skill 的 AI 助手加载的技能包，不是独立聊天应用。包内 Python 脚本负责选题、记录和统计；情境理解、反馈、改写和评分由宿主助手完成。

## 快速开始

### 1. 放置技能包

解压后，将完整的 `talkeq/` 文件夹放入宿主支持的 Skill 目录，保留内部相对路径。具体目录和加载方式以宿主配置为准；确保加载的是包含 `SKILL.md` 的文件夹，避免重复嵌套成 `talkeq/talkeq/`。

不要只导入 `SKILL.md`：教学参考、题库和脚本也是本技能的一部分。Python 脚本需要宿主能访问本地文件并执行 Python；无法执行脚本时，助手仍可依据教学框架开展无记录的对话训练。

### 2. 首次调用

在能够加载该技能的会话中输入：

```text
使用 $talkeq 介绍训练规则，列出九大板块和可复制的练习提示词，让我选择。
```

首次调用会展示规则和完整菜单。导入文件本身不会自动启动训练或弹出欢迎消息。若首次调用已指定板块，助手会在介绍后直接进入该板块。

### 3. 选择板块并回答

```text
今天练团队沟通，给我一道情境题。
```

助手一次给一道题。你先回答，再获得反馈；必要时重写，最后带走一条可执行要点。无需预先设置训练计划，也无需启用个人记录。

## 九大训练板块

| 编号 | 板块 | 主要练习目标 | 可复制提示词 | 脚本模块 |

| 3 | 信息分层 | 先给必要结论，再按需要补充背景 | 今天练信息分层，帮我判断该说多少。 | `layering` |
| 4 | 注意力边界 | 主动提供必要背景，让额外阅读和参与可选择 | 今天练注意力边界，避免给别人增加阅读负担。 | `attention` |
| 5 | 情绪回应 | 区分倾听、共情、建议与行动，练习修复误会 | 今天练情绪回应，给我一个朋友倾诉的情境。 | `emotion` |
| 6 | 发送前暂停 | 判断联系的目的、时机，以及何时停止 | 今天练发送前暂停，帮我判断一条消息该不该发。 | `pause` |
| 7 | 关系边界 | 表达界限、拒绝、尊重对方的自主空间 | 今天练关系边界，练习表达自己的界限并尊重对方。 | `relationship` |

可以输入编号、板块名称或完整提示词，也可以随时换板块。当前内置 **9 道基础题，每个板块 1 道，每题 3 档附加条件**；助手也可按教学框架生成新情境。

## 训练流程与使用示例

### 一次完整训练

1. **情境**：助手给出背景、问题和适用的附加条件。
2. **作答**：你写出自己会说的话或会采取的做法。
3. **反馈**：指出做得好的地方、最需要改进的问题、对方可能的理解，以及具体改法。
4. **重写**：有必要时再尝试一次，避免只看参考答案。
5. **要点**：总结一条下次可以实际使用的提醒。

训练通常不会在你尝试之前展示参考答案，也不会因为文字多、内向或表达风格不同直接扣分。

### 直接修改真实消息

```text
使用 $talkeq 帮我修改这条消息，保留自然口吻，先给改写，再说明最重要的改动：
“你上次说要给我的东西怎么还没给？我这边都没办法继续了。”
背景：我需要同事确认页面文案，才能安排开发。
```

这类请求直接处理消息，不要求先做情境题。提供沟通对象的角色、你的目的和必要背景即可，不必提供真实姓名或完整聊天记录。

### 复盘误会

```text
帮我复盘这次沟通：我想表达什么，对方可能听成了什么，怎样补一句能把事情说清楚？
以下是经过匿名处理的对话：……
```

### 自主安排混合训练

```text
今天你来选板块，给我一道情境题，优先复练本次对话里暴露的问题。
```

只有你授权由教练选择或进行混合训练时，才跨板块调度；明确指定的板块优先于薄弱项推荐。

## 语言、习惯与提醒

### 语言

默认跟随当前交流语言，也可以明确指定：

```text
使用 $talkeq，接下来用英语训练团队沟通。
```

规则、菜单、题目和反馈会使用选定语言。未设固定语言时，中途切换交流语言也会同步切换；仅引用外语材料不代表改变训练语言。文件路径、命令、模块名、题目 ID 和记录标签保持原样。

题库及脚本输出的情境文字是中文，助手在展示时负责转换为选定语言；脚本没有语言切换参数。

### 可选训练习惯

默认按需训练，不设固定周配比、每日次数或板块轮换。需要时可以说：

```text
设置训练习惯：每天 2 次，第 1 次团队沟通，第 2 次关系边界，每次约 5 分钟。
```

可以随时改次数、换板块、暂停或取消。本次明确指定的板块优先于习惯安排。当前会话可以沿用安排；跨会话保存需要选择私人位置，并将训练偏好单独保存，不能直接塞进脚本的成绩状态文件。

### 提醒

设置训练习惯不会自动创建提醒。若需要定时提醒，需另行提出，并由支持提醒的宿主工具处理。`coach.py` 不包含后台服务、定时任务或通知功能。

## 命令行使用

### 运行环境

- Python **3.9 或更高版本**。
- 仅使用 Python 标准库，无需 `pip install`。
- 脚本无需 API key、不联网、不调用语言模型。
- 以下命令均在 `talkeq/` 文件夹内执行。路径包含空格时请用引号包裹。

上述离线特性只针对本地脚本。与宿主 AI 助手聊天的数据处理方式取决于宿主，并不因此变成全程离线。

### 获取情境：`next`

不使用持久记录，获取一题：

```bash
python3 scripts/coach.py next
```

指定板块：

```bash
python3 scripts/coach.py next --module team
```

根据已有记录，获取指定板块的题目：

```bash
python3 scripts/coach.py next --state "/你的私人目录/coach-state.json" --module relationship
```

`--state` 和 `--module` 均可省略。不传 `--state` 时，每次按初始状态选题；无模块限制的调用允许脚本在整个题库内选择，助手在对话中这样使用前应获得混合训练授权。

返回 JSON 中的主要字段：

| 字段 | 含义 |
| --- | --- |
| `id` / `module` | 题目 ID 和所属板块 |
| `title` | 情境标题 |
| `situation` / `question` | 展示给用户的背景和问题 |
| `focus` | 供教练评估使用的训练重点 |
| `fingerprints` | 题目对应的薄弱项标签，用于调度，不是对用户的判断 |
| `level` / `challenge` | 当前难度及对应附加条件 |

`next` 只读取状态，不创建文件，也不把“出过题”记为“完成训练”。因此没有新增记录时重复调用，可能返回同一道题。

### 保存一次结果：`record`

只有选择持久记录后，才使用此命令。请将示例路径替换为自己选定的私人可写位置；不要放在技能安装目录中。

```bash
python3 scripts/coach.py record \
  --state "/你的私人目录/coach-state.json" \
  --scenario team-1 \
  --score 1 \
  --fingerprints topic-drift
```

没有需要记录的薄弱项时，省略 `--fingerprints`：

```bash
python3 scripts/coach.py record \
  --state "/你的私人目录/coach-state.json" \
  --scenario team-1 \
  --score 2
```

| 参数 | 要求 | 说明 |
| --- | --- | --- |
| `--state` | 必填 | 本地 JSON 状态路径；文件和父目录不存在时会创建 |
| `--scenario` | 必填 | 必须是当前题库中已有的题目 ID |
| `--score` | 必填 | `0`、`1` 或 `2`，由助手结合回答评定 |
| `--fingerprints` | 可选 | 以空格分隔，最多 2 个不同的受控标签；默认空列表 |

成功时返回 `recorded`、累计 `attempts` 和当前 `level`。每次成功调用都会追加一条记录，同题复练也一样；命令不去重，不应因返回结果不明确而盲目重试。

### 查看统计：`report`

```bash
python3 scripts/coach.py report --state "/你的私人目录/coach-state.json"
```

返回累计次数 `attempts`、当前难度 `level`、各板块次数 `module_counts`，以及最近 12 次记录中重复出现的标签 `recurring_fingerprints`。

`report` 只读。指定的状态文件不存在时，按初始状态返回 0 次、难度 1，不会创建文件。

### 查看完整帮助

```bash
python3 scripts/coach.py --help
python3 scripts/coach.py next --help
python3 scripts/coach.py record --help
python3 scripts/coach.py report --help
```

## 评分与自适应安排

### 0–2 分标准

| 分数 | 含义 |
| --- | --- |
| 0 | 核心目标未达成，或明显越界 |
| 1 | 目标部分达成，需要一次关键修改 |
| 2 | 信息、行动或边界已清楚，且语气适合情境 |

评分是对本次表达的反馈，不是人格、情商或关系质量测量。脚本只保存传入的分数，不读取回答或自动打分；信息不足时应先澄清。

### 受控薄弱项标签

每次只记录最明显的 0–2 个标签。

| 标签 | 说明 |
| --- | --- |
| `topic-drift` | 当前问题未结束就加入无关话题 |
| `context-overload` | 不必要背景淹没关键信息或行动 |
| `unclear-action` | 执行任务缺少责任、事项或完成标准 |
| `attention-burden` | 要求对方自行翻找本应直接提供的关键信息 |
| `premature-advice` | 对方需要倾听时抢先给建议 |
| `contact-pretext` | 为获得回应制造不必要的联系理由 |
| `mind-reading` | 把模糊信号当成确定心意 |
| `boundary-pressure` | 忽略拒绝或施加互动压力 |

### 选题和难度如何变化

- 在最近 **12 次记录**中，同一标签至少出现 **2 次**才作为重复模式。
- 先按指定模块筛选；若有多个候选，排除最近一次记录的题目，然后优先安排重复薄弱项。
- 后续按模块累计练习次数、题目最近练习位置排序，最后以题目 ID 打破平局；选题不是随机抽取。
- 每累计 **3 次记录**评估一次最近 3 次成绩：全为 2 分则升 1 档，至少两次 0 分则降 1 档，否则不变。难度范围为 **1–3**。
- 当前难度是整份状态共享的，并非各模块单独计算。

当前每个模块只有一道基础题，因此指定模块时仍会重复该题；难度变化主要体现在附加条件。更多变化可由助手生成，或由维护者扩展题库。

## 记录格式与隐私

默认不保存个人训练记录。启用后，脚本生成的状态文件结构如下：

```json
{
  "version": 1,
  "level": 1,
  "history": [
    {
      "at": "2026-09-23T12:00:00+00:00",
      "scenario": "team-1",
      "module": "team",
      "score": 1,
      "fingerprints": ["topic-drift"]
    }
  ]
}
```

时间由脚本以 UTC 生成。每条记录只写入题目 ID、模块、时间、分数和受控标签，不写入回答、聊天原文或姓名；状态文件不是加密存储，也不包含训练习惯。

- `next`、`report` 只读，只有 `record` 写入。
- 写入采用临时文件和原子替换，但没有多进程合并；避免多个进程同时写同一状态文件。
- 保留状态文件即可继续使用这些结构化历史；不代表助手记住了完整对话。
- 删除自己选定的状态文件可清除该脚本的持久记录；这不会删除宿主的聊天历史或其他备份。
- 状态损坏时先保留原文件并排查，不能靠反复写入修复；可暂时继续无记录训练。

对真实关系问题，训练区分事实、合理解释和未知，不凭单个表情或回复速度判断他人心意。技能不用于心理诊断、操控他人或施压追求，不自动发送消息，也不自动上传记录。涉及威胁或强迫时，应优先回应安全需要。

## 扩展题库

在 [assets/scenarios.json](assets/scenarios.json) 的数组中加入新对象。下面是可供维护者添加的示例，**默认题库尚不包含它**：

```json
{
  "id": "team-2",
  "module": "team",
  "fingerprints": ["topic-drift", "unclear-action"],
  "title": "上线前同步",
  "situation": "上线检查还缺一项付款验证。测试同事下午有空，负责人希望今天明确能否上线。",
  "question": "请写一条帮助团队确认下一步的群消息。",
  "focus": "阻塞项、责任确认、下一次同步时间",
  "challenges": [
    "没有额外条件。",
    "负责人希望你先用一句话说明现状。",
    "另一位同事同时提出一个与本次上线无关的新需求。"
  ]
}
```

维护时注意：

1. `id` 必须唯一；已有状态引用的 ID 应保留，且不要随意改变其所属模块，否则旧状态会校验失败。
2. 现有九个模块名见上表；`fingerprints` 使用脚本 `TAGS` 中的受控标签。
3. `challenges` 提供按难度 1、2、3 排列的三个字符串；保留其余展示和评估字段。
4. 题目应围绕同一训练目标设计实际不同的情境，而不只是替换人名。
5. 助手临时生成的题目可以用于对话训练，但只有加入题库并拥有有效 ID 后，才能用 `record` 记录。

若要新增标签，需要同步修改 `coach.py` 的 `TAGS`、评分说明和相关题目；若要新增模块，还需同步技能菜单、教学框架与展示说明。题库目前没有独立的完整结构校验器，维护后应验证 JSON 并实际试跑受影响的模块。

## 验证与常见问题

### 运行现有测试

在技能根目录执行：

```bash
python3 -m unittest discover -s scripts -p 'test_*.py'
```

现有测试覆盖只读行为、记录持久化、难度上下限与降低、薄弱项调度、避免立即重复，以及无效状态／输入下的文件保护。测试使用临时目录，不需要真实训练记录。它们验证脚本行为，不验证 AI 的教学质量或所有自定义题库字段。

修改题库后还可运行：

```bash
python3 -m json.tool assets/scenarios.json
python3 scripts/coach.py next --module team
```

### 导入后为什么没有反应？

导入不等于调用。确认宿主加载了完整文件夹，然后明确输入 `使用 $talkeq 介绍训练规则`。必要时按宿主的方式重新加载技能或开启新会话。

### 运行脚本为什么没有聊天或反馈？

脚本输出 JSON，只做调度、记录和统计。需要由加载技能的助手与你对话，或由你自行读取输出；它不是独立的 AI 教练。

### 为什么反复出现同一道题？

当前每模块只有一道基础题；此外，`next` 不写历史。未使用记录、未追加新成绩或仅指定单个模块时，重复是正常的。可以让助手生成同目标的新情境，或扩展题库。

### 为什么记录后没有升难度？

难度每 3 次累计记录才评估一次，最近 3 次必须全为 2 分才升级，且最高为 3。单次 2 分不会立即升级。

### `--scenario` 或 `--fingerprints` 被拒绝怎么办？

检查题目 ID 是否存在于当前题库，标签是否属于受控列表，且一次最多 2 个不同标签。可以运行 `record --help` 查看当前允许值。不要直接用临时生成的题目名称当作 ID。

### 状态文件报错怎么办？

检查 JSON 是否完整、`version` 是否为 1、难度是否为 1–3，以及历史中的题目 ID 和模块是否仍与当前题库匹配。先备份并保留原文件，不要覆盖排错；也可选择新的私人状态路径从头开始。

### 需要联网、账号或付费 API 吗？

本地脚本不需要。对话训练需要可加载技能的 AI 宿主，其账号、联网和计费条件由宿主决定，本包未实现模型接口。

### 能自动提醒或记住上一次的安排吗？

脚本不能自动提醒。跨会话成绩依赖你授权保存的状态文件，训练习惯则需要单独保存；未保存时，新会话可能需要重新提供安排。
